# Full Rust cutover

The destination is one Rust service that owns the MCP session, OBS connection, cooperating control state, recording jobs, recovery journals and media workers. OBS and FFmpeg remain native applications controlled by that service. JavaScript is a temporary compatibility runtime; Zig has no measured role in this architecture.

As of 1 November 2026, the default transitional candidate serves 59 simple OBS reads, offline request description, scene-template planning, structural scene audit, three offline prompts, static resource-template discovery and live resource listing in Rust. Its other **116 of 178 default tool routes** retain TypeScript ownership. Default routing and compatibility packaging have not been removed.

The separate `OBS_MCP_NATIVE_STATEFUL=1` lane has a declaration union of 165 routes and exposes up to **162 with all approved recording/media adapters: 102 explicit service handlers, 59 reads, and offline request description**. Its immutable Service configuration omits Stream Start/Stop/Toggle whenever Take or file-media adapters are present, because those stream controls can asynchronously change recording. Standalone native stream sessions retain these routes. The persistent owner includes production observation, staging/transition, bounded take supervision, preparation/recovery, manual snapshots, guarded property lists, cooperating leases, planning/audit, media jobs and 75 closed command tools in the capture-capable profile. It additionally owns manual ACK-only StopRecord, offline prompts, resource listing/readers and scene-name completion. Source and extracted-package receipts qualify each frozen composition separately. Checkpoint 161e is the latest live Mac-qualified artifact; default routing is unchanged.

One persistent Rust service owns the physical OBS session, observer, shared control state, stage/take jobs and journals. Unsupported tools/interfaces return explicit capability errors and retain native state; this lane never starts the SDK runtime. It requires an existing canonical approved state directory. Recording requires an explicit approved `OBS_MCP_NATIVE_RECORDING_ROOT`; media tools additionally require existing FFmpeg/ffprobe. The full inventory is conditional on those prerequisites and tool filters. Preflight without its approved host probe remains explicitly unavailable. Status can truthfully report disconnected metadata without connecting; millisecond sleep is an offline cancellable local timer, while frame sleep requires live video settings.

## Standalone product endpoint

The desired endpoint is an independently identifiable Rust product, with MIT as the intended license for application code once the retained components' rights and provenance support that choice. Dependency licenses remain separate; this does not require every dependency to use MIT. The present GPL declarations and dependency gate remain in force during the mixed distribution.

Cutover includes removing the compatibility runtime and its production payload, establishing an owned registry and help/prompt text, replacing inherited identity assets and documentation where necessary, and recording authorship or permission for retained material. Functional OBS wire identifiers remain interoperability facts. Required notices and the provenance record remain available.

## Sequence and acceptance

| Dependency | Rust responsibility | Acceptance at its real boundary |
| --- | --- | --- |
| Protocol and identity | Frame admission, protocol era, request identity, filters, schemas, cancellation and child cleanup | Both pinned MCP client modes; malformed/concurrent/abandoned requests; no identity reuse or surviving owned child |
| Observation | One socket actor, bounded queues, connection tokens, event cursor, workflow-specific evidence profiles | Real socket ordering; queued events before reply invalidate the right sample; exact ordered SDK read comparisons; actor and observer exit before handoff |
| Shared control and journals | Caller precedence, lease, take lock, confirmation, dispatch-time checks and one receipt writer | Actual SDK policy oracle; real filesystem publication faults; uncertain effects stay uncertain; cancellation resumes one observer without replay |
| Stateful service owner | Combine those owners; retain one journal backend and lend scoped publication ports to composed operations; own stage and take state | No two mutation owners; stale tokens, expiry, concurrent access and changed connection refuse before send; no SDK handoff that discards live Rust state |
| Scene and capture workflows | Audit, role planning, source-aware discovery, snapshots, preparation, stage, transition and guarded recovery | Public contracts, exact target identity and ordered effects; property enumeration remains denied on unsafe paths; conflicting human edits survive recovery |
| Recording and media | Preflight, bounded take timer, monitor, stop reconciliation, strict decode, trim/export and publication | A silent fixture take of at most 10 seconds; actual file decode and A/B content evidence; resistant decoder exit; no output publication after failed validation |
| Remaining MCP interfaces | Resources, prompts, rich elicitation, dynamic toolsets, HTTP authentication/origin handling and notifications | Existing SDK fixtures and real client journeys; state and error semantics agree across transports |
| Configuration and distribution | Native saved authentication, TLS, dependency notices, host packages and CI | Secrets stay opaque; encrypted endpoints verify certificates; dependency gate passes; extracted bundles work on each claimed platform |
| Remove compatibility | Delete Node runtime payload and routing only after all promised interfaces have a qualified native owner | Consumer install/start without Node; complete inventory/contracts, recording/recovery, platform and packaging checks; no compatibility escape counted as native success |

These dependencies can overlap as library work. The qualified subset now has a public opt-in combined owner; default cutover still waits for the remaining routes and interfaces. An RPC acceptance is weaker than an observed postcondition; a structural audit is weaker than rendered-content evidence; a process-drop fallback is weaker than a joined cleanup receipt.

## Boundaries that still need resolution

Native TLS remains open under the project's GPL-2.0-only license. The current gate rejected the predecessor Apache-2.0 AND ISC dependency. WSS therefore stays encrypted on the SDK path. The official Rust MCP SDK has not been adopted; protocol work must retain the current contract or use a separately reviewed compatible implementation. See [dependency review](native-dependencies.md).

The predecessor observation signature uses JavaScript locale collation. The Rust observation adapter currently qualifies ASCII identifier keys and refuses unsupported property-key alphabets. Stage fingerprints now use a separate private, versioned codec that covers Unicode setting keys and source-compatible numeric values. Those fingerprints stay within the owning stage machine; they are not exported as public observation signatures or recovery hashes.

Version-2 preparation journals now persist intent, possible dispatch, acceptance and uncertainty per field before effects become restoration authority. Actual subprocess restart controls cover publication and dispatch fault schedules; version-1 attempted journals remain conservatively unknown, and the predecessor refuses the new format before writing. Current-state readback never upgrades uncertain dispatch into permission to restore. The concrete same-session demo adapter has filesystem/reopen, human-conflict and lost-reply controls. The public opt-in service has also passed full SDK result/effect comparisons, retained-frontend, restart-uncertainty and human-conflict controls. These checks do not prove power-loss durability or defeat same-user rollback of a complete valid history.

The combined service retains one receipt broker and lends typed publication scopes to retained stage/take/setter jobs. A scope cannot update another operation, and its dispatch guard expires with the port. Frontend cancellation does not end admitted work or release publication custody before settlement. Deadlines discard late evidence after draining the same admitted operation; they do not grant replay authority. Local timers share one cancellable implementation and need no OBS socket. EOF signals owned Service shutdown alongside retained frontend drain and joins both. A single writer bounds encoded stdout retention independently of input progress; output exhaustion still performs owned cleanup and reports failure after queued output settles. A direct-process control proved clean exit with an admitted50-second timer without SDK kill fallback.

Stage admission explicitly requires transform events because OBS `All` omits them; take supervision additionally requires meter events. Meter telemetry advances delivery watermarks without invalidating structural evidence; settings and audio-state changes still invalidate it. A late accepted preparation mutation event may invalidate post-ACK evidence. The qualified fix permits a bounded read-only resample and verifies the expected state while preserving human-conflict fences, including edits during resampling. It never repeats the mutation.

The source and Rust monitor now refuse to infer a qualified unchanged interval from warmup alone. Comparison qualification follows compatible median windows; changed-size, paused or retired program history resets that authority, and late samples from retired history cannot publish. An empty still list reports no qualified unchanged stretch, not proven motion. The archived live artifact predates this correction; the corrected monitor has automated source/consumer controls plus the later artifact's bounded live run.

A parser's bounded history is distinct from bounds on active jobs and process memory. The opt-in service separately bounds retained read/frontend jobs and two media jobs. OBS receive frames allow the 8 MiB base64 body of a 6 MiB image plus 64 KiB envelope allowance, while request/event encoded-byte budgets remain unchanged. Custom image limits are honored; invalid policy refuses staging before connection or effect.

The concrete media backend has been checked on this Mac with installed FFmpeg/ffprobe: a generated SDR red/blue fixture passes encoding, metadata and chapter checks, strict decoding, pixel sampling and no-clobber publication. Contact-sheet output matches the predecessor byte for byte for explicit and default layouts. Private work files remain owned until children settle; uncertain cleanup preserves evidence. File inspection measures bounded PCM samples rather than parsing diagnostic text, which prevented a reproduced false-silence result from a crafted filename. Closed local-input protocol and container lists prevent disguised playlists from fetching network media. These generated file fixtures do not establish Linux desktop qualification. The archived bounded OBS recording is separate evidence for its named binary. Public opt-in contact-sheet/trim results now also match the full SDK registry wrapper, including images, durations, proof hashes and structured results. Media jobs use the same OBS session for fresh status/directory checks, retain workers through cancellation and cleanup, refuse conflicting recording starts, and do not publish after a changed-directory fence. Qualification conservatively denies file-media operations during any active recording.

The remaining **13 unported Source routes** cover five recording/named-output controls, five raw/batch/vendor/hotkey routes, two multi-step workflows and manual snapshot restore. Capture-capable native sessions additionally exclude Stream Start/Stop/Toggle. Their 75 closed command tools include bounded opaque settings, input and transform readbacks, recording timeline controls, six UI callbacks, two confirmed Virtual Camera/Replay Buffer starts and two atomic toggles. Direct Virtual Camera and Replay Buffer Stops are ACK-only; Stream Stop remains ACK-only in standalone stream sessions. Manual StopRecord has a separate typed recording-impact adapter and broker scope, sharing the existing bounded safety queue and sole physical writer. Its dispatch revokes older Take authority before reply or formatting; an ACK does not grant file inspection. Take admission reserves its original impact ticket before asynchronous binding, preventing a delayed initialization from recapturing authority after a manual Stop. Unknown, orphaned or unavailable journal evidence still refuses new dispatch. The owned Take Stop retains its separate reservation. This does not promise unlimited Stop admission, progress through an already-flushing TCP frame, or availability when storage is unavailable. Source's explicit profile/collection/output-setting lock is preserved. A successful mutation ACK remains Accepted even if its later readback fails; a lost ACK starts no readback and grants no replay.

The permanent single-writer broker and strict metadata-only GenericV2 receipt format are implemented. Full validated inventory determines admission before the64-entry display projection. Generic Accepted remains weaker than observation and permits only another explicit independent command; it never becomes replay or restoration authority. Critical V1 Accepted and all Dispatching/Unknown uncertainty remain blocking. Take admission reserves start/stop headroom against all physical receipt files, and unrelated work cannot steal the owned stop slot. Bounded FIFO commands preserve their original deadlines; queued cancellation/expiry sends nothing, while control and owned stop bypass that queue. Real SIGKILL/restart and filesystem-identity controls pass; post-rename fsync failure and power-loss durability have not been simulated by the new broker tests.

A bounded first-terminal output-event provider is implemented as a separate prerequisite: one observer, fixed subscription slots, charged path lifetime, immutable registration deadline and finite projection settlement. Actual socket controls distinguish an event received before the deadline but processed later from an event that arrived too late. The latter cannot consume another waiter’s path budget. The provider itself does not authorize starts or toggles, create a second socket, or change ACK custody. The explicit start adapters retain their original Source confirmation prefix and first terminal result through settlement. Cam/Replay toggle callbacks now preserve the single atomic request and Source result formatting. Recording starts/toggles remain unported. Stream confirmation does not establish completion of automatic recording effects; it is excluded from sessions with Take/media adapters.

Mixed native streaming and owned recording/media needs a qualified host-side completion contract. The pinned websocket handler returns before queued frontend work, and built-in HLS can signal StreamStarted before automatic recording begins. Fixed waits, status samples and uncorrelated vendor events are insufficient. Current feature separation is enforced at both public discovery/direct dispatch and Service admission; it is an intermediate compatibility restriction.

Other open interfaces include native TLS, HTTP/authentication/origin handling, client-initiated features and elicitation, enabled live confirmation, dynamic toolsets/notifications and resource subscriptions. Common client metadata/capability offers and scene-name completion are supported; accepted offers do not enable the associated client features. Default mode retains SDK ownership for unported interfaces; opt-in mode refuses them without handoff. First lazy connection/bootstrap is bounded but can delay handling of incoming frames.

Owned Take Stop has reserved frontend capacity and one separate transport slot for its fresh recording-status checks and StopRecord. Actual public controls send Stop before releasing an unrelated held mutation or input-readback reply, and preserve a replacement human recording. Ordinary RPC failure still retires the connection conservatively; monitor cleanup and final reporting may wait for ordinary work after physical Stop. Profile output-setting ACKs set the physical owner's restart-required flag before durable outcome publication; profile switches do not clear it. New physical owners begin with a fresh client-local flag.

A prior read-only Linux VM readiness check found Rust 1.95.0 and FFmpeg, but no OBS installation, running display server or established capture/portal route. Linux desktop, Wayland and Windows remain unqualified. Local fake-OBS tests do not fill that gap. This isolated candidate still requires integration against the current main branch; dependency changes require requalification.
