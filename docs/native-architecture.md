# Native migration

The native entry point is a Rust executable built with the pinned Rust 1.95.0 toolchain. Its default transitional mode serves discovery, all three offline prompts, static resource-template discovery, live resource listing, 59 eligible read-only OBS routes, offline `obs-describe-request`, qualified read-only `obs-plan-scene-template`, and structural `obs-audit-scene` without starting a JavaScript runtime. All 178 tools remain available in that mode; the other 116 tool routes, stateful workflows, resource reads/subscriptions and elicitation use the included TypeScript compatibility server.

The separate `OBS_MCP_NATIVE_STATEFUL=1` mode owns a persistent Rust service. With all approved recording/media adapters it exposes up to **163 candidate tools: 103 explicit service handlers, 59 qualified reads, and request description**. Its declaration union contains 166 routes: Stream Start/Stop/Toggle are available only in sessions constructed without owned Take or file-media adapters. OBS stream controls can asynchronously start/stop recording, so the immutable Service configuration excludes that unqualified combination before discovery or dispatch. The mode never starts the SDK runtime. Current additions include two confirmed Virtual Camera/Replay Buffer starts, their two atomic toggles, and manual ACK-only recording Stop. Source and extracted-package receipts qualify each frozen artifact separately; the latest completed live Mac qualification is 162b, using the public Record Clip route. Default 178-tool routing and 116 compatibility routes are unchanged.

This is a gradual migration. Every TypeScript source still has an explicit compatibility owner in `native-migration-ledger.json`; a route implemented in Rust does not mean its entire source module has been ported. The project start command uses the native executable after `npm run native:build`; `npm run start:compat` and the existing Node package remain available for compatibility.

## Default transitional session owner

A new default stdio session starts in Rust. The tool contract is generated from the actual MCP SDK registration, including input/output schemas and annotations. Native routing is an explicit allowlist of simple read-only request tools. Argument defaults, unknown-field stripping, Unicode length semantics, response extension fields and supported schema constraints are checked before returning native results. Unsupported validation/protocol features go to the SDK. Read-only annotations alone never admit native property enumeration: `GetInputPropertiesListPropertyItems` always stays behind the established source-aware guards.

On the first compatibility operation, Rust closes and drops its OBS session before starting one exclusively owned SDK child. That child owns every subsequent request for the lifetime of the MCP session, including otherwise eligible reads. Leases, take locks, confirmation, generations, resources, recording deadlines, durable receipts and recovery therefore retain their existing owner. A consumed stage token cannot be replayed through another backend.

Default fast-path native reads have a bounded whole-operation deadline, frame limits, socket-bound identities and no transport replay. A native read failure can move the session to the SDK and repeat only that unanswered read. Mutations are never dispatched by the Rust fast path. Cancellation closes the native read session; it does not claim cancellation of an OBS effect.

The full-Rust migration's first tranche gives protocol admission one explicit owner: fresh, modern, legacy-initializing, or legacy-ready. Duplicate initialization and cross-era switches leave the native lane. Admitted response contexts retain their request identity and era together. Legacy replay retains at most two frames and 16 MiB, with the existing 8 MiB per-frame limit. OBS request identities use typed generations and nonzero sequence numbers; exhausting either counter permanently retires the allocator rather than wrapping or resetting it on reconnect.

Modern `2026-07-28` inline metadata/discovery and legacy initialization are checked with the pinned TypeScript client. Legacy handshake history is replayed into the child while its historical responses are suppressed. Unknown metadata and richer client capabilities stay with the SDK. In default mode, HTTP, CLI and explicit custom screenshot-size configuration replace the process with the existing server. Dynamic toolsets and confirmation select compatibility before tool dispatch. Explicit false/all MCPB defaults retain the native path.

Prompt text and resource-template definitions are generated from the actual SDK registration and embedded at build time. Prompt arguments preserve the source's defaults and supported JavaScript numeric forms. Substitutions scan the original template once, so user text cannot become another template directive. Unsupported argument shapes retain SDK validation. Prompt and template listing require neither an OBS connection nor a JavaScript child. Live resource listing uses one read-only `GetSceneList` and source-generated static/dynamic metadata. It preserves scene order, duplicate names and `encodeURIComponent` spelling, independently of tool-group filters. Unsupported limits and peer errors hand off the whole session; status/take resource reads and subscriptions retain SDK ownership.

Static `OBS_MCP_TOOLSETS`, `OBS_MCP_TOOLS` and `OBS_MCP_READ_ONLY` selection runs in Rust. Group assignments come from the actual SDK registry. Read-only mode takes precedence over explicit selections; invalid or empty selections fail at startup. Calling a hidden tool transfers to the SDK for its established refusal before any native dispatch. Differential tests compare both protocol eras, registry order, schemas, selection precedence and JavaScript whitespace behavior. Dynamic toolsets remain together with their SDK state and notifications.

`obs-describe-request` reads an immutable embedded copy of `docs/protocol.json`. Exact lookups, ordered listings, category filters and unknown-request errors require no OBS socket or JavaScript child. The explicit native-local manifest entry and its input schema must agree with the implemented handler before admission. The migration ledger binds the embedded protocol data as a build input; changing it invalidates the seal.

`obs-plan-scene-template` uses a subscribed Rust session actor and a bounded read-only observation. It closes the fast-read socket before opening that actor and joins both the actor and its event observer before replying, cancelling, or handing off. The observer publishes event revisions before advancing its processed cursor; a read waits through the event watermark captured after its RPC reply. Queued events therefore cannot appear to be unchanged evidence. Connection tokens bind the cursor to its owning socket. Successful plans describe proposed changes; they apply nothing and make no rendered-content claim. Unsupported transport and peer-error projections retain the SDK interpretation after native cleanup. The exact manifest entry, input schema, registration and literal-transform validation gate admission.

Opt-in saved OBS authentication resolves in Rust. An explicit environment password wins; disabled opt-in reads no file. Native candidate paths follow the host's OBS config layout, including Linux Flatpak, and diagnostics report only the source path. Malformed JSON, unsupported encoding or files over 256 KiB select the SDK before native dispatch; they are not reinterpreted as missing credentials. Fixture tests compare actual TypeScript paths, precedence and diagnostics, authenticate real loopback sessions in both MCP modes, and check that logs contain neither fixture password. No config is written by this resolver.

`obs-audit-scene` retains its source-specific 512-read, 12-second and UTF-16 evidence budgets. Its event profile ignores unrelated program changes while still accounting for every received event in the cursor barrier. It supports named canvas selection and bounded optional screenshots, with a 512 KiB report limit. An image supports separate visual review; neither a structural pass nor a syntactically accepted image payload establishes rendered correctness.

Encrypted `wss:` endpoints also select compatibility before native dispatch. The dependency review found an Apache-licensed TLS dependency incompatible with the project's declared GPL-2.0-only license. Native TLS was removed without downgrading encrypted endpoints; a compatible, qualified TLS backend remains a full-cutover requirement. The current offline gate reviews 61 resolved packages including the application, selecting explicit compatible license alternatives where available. It rejects unreviewed inventory changes. See [dependency decision and limitations](native-dependencies.md). No official Rust MCP SDK dependency or code was adopted.

A Stream ACK, StreamStarted event or currently inactive RecordStatus cannot establish that OBS has finished queued automatic-recording effects. This boundary coordinates one native owner; independent controllers and human actions remain external inputs.

One `Service` owns the physical OBS session, subscribed observation bridge, shared control state, stage machine, take supervisor and receipt writer. Manual StopRecord uses the existing bounded safety queue and sole physical writer. Its recording-impact ticket is reserved before asynchronous Take initialization; dispatch revokes older Take authority, and a known ACK remains distinct from file inspection. Lost replies never authorize replay, replacement-recording Stop, or file access. It transfers preparation/snapshot journal owners once into this service. Planner/audit jobs, the 59 reads and custom read callbacks use the same session; they do not open fast-path or temporary workflow sockets beside it. Actual cached `GetVersion` capabilities/platform remain optional when unknown. A connection test performs a fresh version request. Status reports actual local connection facts without forcing connection; millisecond sleep and invalid sleep-selection refusals are offline. Frame-based sleep reads the live frame rate.

The lane also serves the three offline prompts, full resource listing, two resource-template definitions, `obs://status`, `obs://scenes`, `obs://take/current`, scene-items/screenshot readers, and scene-name completion. An inactive take resource is available offline. Scene lists and completions enforce explicit bounds without truncating evidence silently. Template names undergo one URI-component decoding pass; screenshots reuse the source parser. Common client metadata and capability offers are validated without enabling roots, sampling or elicitation features. Resource subscriptions and richer SDK semantics remain unowned. Unsupported tools/methods return explicit capability errors while preserving native state; hidden tools cannot bypass filters. HTTP, CLI, WSS, dynamic toolsets and enabled live confirmation cannot silently escape into the SDK. Custom screenshot limits are qualified here: default 4 MiB, maximum 6 MiB decoded image bytes. Invalid policy refuses staging before connection/effects and remains an explicit screenshot-tool error.

Frontend reply contexts are bounded and retained independently from service-owned work. Unrelated frames can receive replies while a stage inspection or local timer is pending. Explicit cancellation may suppress the frontend reply, but admitted OBS/process work remains owned through settlement and cleanup. Local timers can stop immediately through the shared cancellation signal; dropping those effect-free timers is distinct from abandoning RPC or media work. EOF signals Service shutdown while retained frontend work drains. Both owners must join before the process exits; the Service joins its admitted OBS work before retiring the observer and socket. A direct-process test with an admitted 50-second timer observed clean exit code zero, without a client transport's forced-kill fallback.

One retained writer owns stdout and serializes complete JSON lines through flush. Reply admission never waits for the client to read. At most 128 frames and 32 MiB of encoded line bytes are retained across queued and actively written frames; permits remain held through partial writes and flush. This bounds the encoded output pool, not parsed Values, allocator overhead, Tokio buffers or process RSS. Exhaustion closes frontend admission and signals owned recording cleanup; previously queued frames drain when the reader resumes, and the process reports an error. An overflowing response is unavailable. A permanently unread pipe may retain the blocking write and prevent final process exit.

An owned Take Stop has one additional frontend job slot beyond the 32 ordinary jobs. Its recording-status checks and StopRecord share a reserved transport slot and 512 encoded bytes, independent of ordinary request capacity. The same socket actor can dispatch these closed controls while one ordinary reply is pending; ordinary requests remain serialized. Fresh status, continuity checks and the final mutation guard still apply. Tests cover both reply orders, cancellation/deadline uncertainty, saturation, and preserving a replacement human recording. A pending RPC's failure still retires the shared connection conservatively. This establishes physical Stop progress after the first ordinary frame has flushed; monitor cleanup and final reporting can still wait for ordinary work. It does not guarantee progress through TCP backpressure or bound aggregate reply memory.

The three direct output Stops acknowledge the RPC only; their fixed success text does not prove inactive output state. They preserve Source lease exemption and remain available during an owned take. A separate extra frontend slot and closed one-item/512-byte transport lane let them dispatch while ordinary work waits. That lane cannot consume the owned Take Stop/status reservation. The Service retains one active public Stop plus at most eight queued commands and 8 KiB of queued argument/caller bytes. Queued work keeps its original deadline and cancellation state. Recording and named-output Stops remain unexposed.

The output-event provider shares the existing sole observer and original event move into the take feed. It retains the first STARTED/STOPPED for four closed output kinds, with at most 32 subscriptions and 8 MiB of owned UTF-8 path bytes. Consumed events keep their path permits until drop; views cannot keep producer admission alive. Registration fixes the confirmation deadline. Late events cannot copy paths, spend budget or produce path errors. At confirmation expiry, a separate finite settlement bound drains the intrinsic received-cursor prefix through this provider’s projection watermark, without waiting for take application. Revocation settles pending waiters; a previously delivered first terminal remains known. These are provider controls, not a public start-tool, output-ownership or file-existence claim. The existing start helper still needs a reviewed adapter for these two deadlines.

A permanent `ReceiptBroker` owns the single operation-store backend behind a short synchronous mutex; no OBS await holds that mutex. Nonclone typed ports grant bounded take, stage, critical-record, closed public-Stop, closed-setter or manual-Restore-batch publication scopes. A port can update only its own durable operation IDs. Only the closed public safety Stops may exclude exact IDs of currently retained live loans in known in-flight phases when checking admission and dispatch. Full inventory/layout validation and an own Dispatching receipt remain required. Unknown, orphaned, missing and poisoned proof never qualifies; ordinary and direct-store guards remain strict. Detected missing live proof poisons this process through loan drop/reclaim, without adding a durable deletion marker for a later restart. Dropping it revokes cloned dispatch guards, and joined cleanup cannot discard sticky publication uncertainty. The take retains its stop timer and event feed while source-permitted setters, staging and scene taking proceed on the same physical session.

Stage transport requires transform events because OBS `All` excludes them; take supervision also requires meter events. Every delivered event advances the ordered cursor, while meter telemetry alone does not invalidate structural evidence. A timeout retains and drains its I/O future before releasing custody or admitting another take. A completed media phase does not cancel the shared operation needed by its successor.

Preparation/recovery uses version-2 per-field provenance journals. Possible/unknown dispatch and unrecovered attempted version-1 history refuse automatic restoration before OBS reads. Accepted preparation can authorize only its recorded guarded restoration; present-state readback cannot create authority for an uncertain write. Subprocess restart controls cover interrupted publication and dispatch schedules, and the old SDK refuses V2 before operational writes. A late accepted mutation event may invalidate the first post-ACK read: the implementation permits a bounded read-only resample, verifies the expected state, and still refuses intervening human edits. No mutation is replayed by that resample.

Media operations have a separate admission limit of two retained jobs. They use the service's original session for fresh recording-status/directory checks and block conflicting recording starts. Qualification conservatively refuses media access during any active recording. Source/executable/work-directory identities, private temporary files, strict decode and the final directory/publication fence remain checked. Cancellation and shutdown join the same admitted operations; successful decoding alone does not authorize publishing after the recording directory changes.

The monitor's source and Rust implementations now qualify an unchanged span only after sufficient compatible median-window evidence. Short warmup, a changed sample size, pause or program-history retirement cannot manufacture a qualified still interval; late samples from retired history are discarded. An empty still list means no qualified unchanged stretch was reported, not proof of motion. Picture checks and file/content review remain separate evidence.

## Lifetime and capacity

The Cargo library's control, receipt, transport, observation, stage, take, preparation and media owners are now composed by the opt-in public service. In default mode, their public stateful counterparts continue through the TypeScript owner. Additional library modules do not become public native routes merely by compiling.

The general session actor owns one authenticated socket, a bounded FIFO and a live event receiver. Requests and retained events consume item and encoded-byte permits. Event overflow, lost replies and cancellation after possible dispatch invalidate the connection; they never trigger replay. Opaque process-unique connection tokens cannot wrap. Explicit shutdown joins the actor and establishes socket exit; dropping the owner alone is not an awaited cleanup receipt.

The custody coordinator binds its store to the session's exact endpoint hash and derives receipt generation from the session token. It persists intent before queueing and evaluates lease, take-lock and confirmation policy again at dispatch. Its whole-RPC deadline begins before persistence. Cancelling a frontend await leaves the same observer owned by the coordinator; resuming does not queue another request. RPC success produces an accepted receipt, never an observed or rendered claim. Filesystem errors after possible publication remain explicit uncertainty. The operation store preserves version-1 TypeScript receipt compatibility and rejects corrupt, stale or replaced storage evidence; preparation V2 is a separate journal contract. Public opt-in workflows supply validated inputs and independent recording/stage ownership checks. V1 critical Accepted remains unresolved for admission. The separate strict GenericV2 format has no Observed phase: terminal Accepted/Rejected does not block a new explicit command, while Dispatching/Unknown, invalid history or publication uncertainty blocks new work. It stores no command arguments or response payloads; acceptance never grants replay or restoration authority. Actual SIGKILL/restart controls preserve possible dispatch without readback promotion.

Native input stdio/compatibility frames are bounded to 8 MiB. OBS incoming frames/messages allow 8 MiB plus a separate 64 KiB envelope margin, so a valid 6 MiB decoded screenshot can traverse its base64 JSON response. This receive allowance does not enlarge outgoing request budgets or retained event permits. Frames retain partial input across cancellation. Default transitional concurrency can hand off to the SDK; opt-in concurrency remains with bounded retained native jobs. Item and encoded-byte bounds do not establish a process-RSS bound; parsing, results and protocol buffers also consume memory.

Shutdown distinguishes pipe drain, leader exit and descendant cleanup. The compatibility child starts in an owned process group. EOF requests normal closure; bounded TERM/KILL escalation targets that group before the leader is reaped. Cleanup waits for the child rather than interpreting a returned timeout as termination. Process groups do not contain descendants that deliberately detach or change groups; external kill of the Rust supervisor is also outside graceful-shutdown guarantees.

There are no custom FFI handles, borrowed pointers or unsafe Rust blocks in this phase. The reference patterns still apply: admission ends before destruction, queued work must retain its owner, and a successful response does not prove cleanup.

## Architecture decisions from the references

The local Bun checkout already has Rust subprocess/allocation owners; it is not evidence for a mandatory Zig service. Ghostty and TigerBeetle show explicit memory, queue and teardown contracts. OpenTUI, walkrs and DuckDB’s bindings clarify identity, handoff and destruction costs. These are source mechanisms, not measured OBS speedups.

See the [full cutover sequence and acceptance gates](full-rust-cutover.md) for the remaining work.

A source-level Rust MCP SDK can support the current protocol, but adopting it remains a separate reviewed decision. The default front implements a narrow observed wire surface and permanently hands richer semantics to the existing SDK. The opt-in service instead retains its qualified stateful workflows in Rust and refuses unowned semantics. Twelve Source routes still lack native owners. The three Stream effect routes additionally remain excluded from capture-capable native sessions. These constraints and transport/protocol gaps require qualification before default cutover.

Zig is deferred: representative warm TypeScript frame sampling is already in hundredths of a millisecond at the current 96-pixel monitor size and approximately 1 Hz sampling. Adding another ABI has no established end-to-end benefit. FFmpeg already performs encoding and complete decoding natively. Neither a Zig kernel benchmark nor a language label would establish faster OBS capture or encoding.

The migration ledger follows [rustify’s source-to-port mapping/ratchet method](https://github.com/ArchAstro/rustify). The work also uses [rust-rewrite’s ownership-first and test-preservation method](https://github.com/Fldicoahkiin/rust-rewrite). Neither external helper was installed into global skills, and no draft stubs or skipped predecessor tests count as migrated behavior. Source references and rejected transfers are retained in the project reference-pattern library.

## Build, check, measure

```sh
# One explicit dependency fetch when needed; subsequent build/check commands are offline.
CARGO_HOME="$PWD/native/.cargo-home" cargo fetch --locked --manifest-path native/Cargo.toml
npm run native:build
npm run native:check
npm run pack:native -- --offline
```

Cargo build and check drivers run from `native/`, so rustup selects the project toolchain rather than an ancestor default. The build disables rustup auto-install. Install the project-selected toolchain separately if unavailable. The native artifact is `native/target/release/obs-mcp-native`; the host-specific bundle is `dist/obs-studio-native.mcpb`. It includes Rust sources, assets, Cargo.lock and the TypeScript compatibility payload. Node.js 20.19 or newer remains required for compatibility workflows. The binary bundle is restricted to its build host platform/CPU; the existing Node package retains its portability.

To launch directly from this checkout, set `OBS_MCP_COMPAT_ENTRY` to the absolute `build/index.js` path and use the Rust binary as the MCP command. `OBS_MCP_COMPAT_NODE` can name the exact Node executable. `OBS_MCP_FORCE_COMPAT=1` selects the compatibility path for comparison. Normal OBS URL/password configuration remains the existing interface; secrets are never command-line arguments or benchmark output.

```sh
node scripts/benchmark-native.mjs --workflows --out /absolute/report.json
node scripts/check-native-migration.mjs
```

The benchmark compares identical tool inventories/results before timing, then measures cold discovery, connected read latency, warm requests and aggregate server/descendant RSS. `--workflows` adds complete planning and audit calls, retaining their connection and cleanup costs; only independently validated timing and physical-generation metadata differ in result comparisons. Cleanup is part of acceptance. Reports distinguish native-only and compatibility paths, runtime versions, release artifact hashes, sample sizes and variance. A lower-bound sampled peak is labeled as such. OBS/FFmpeg time is separate, and synthetic loopback measurements do not establish faster real capture.

Native packaging runs the license gate and migration ratchet before changing staging or replacing an artifact. `--offline` also keeps its production npm dependency installation on the existing cache. The package includes the dependency decision and cutover guide.

The ratchet checks source/native/contract/toolchain hashes and rejects unclassified source or recognized production placeholders. It is a drift check, not proof of translation correctness. Resealing requires explicit review: `node scripts/check-native-migration.mjs --update --adopt-manifest-routes` accepts a deliberate route change; ordinary `--update` only reseals reviewed content. Never use resealing to hide a failing parity test.

## Receipt scopes and concurrent commands

Media admission requires a complete current-endpoint receipt view with no unresolved uncertainty before reading OBS recording status or directory, or starting a file worker. An inactive status read cannot clear a possible recording-start effect. Foreign-endpoint history retains its physical-capacity cost without becoming current-endpoint uncertainty.

The broker validates the full1024-file physical inventory before admission, independent of the64-entry display projection; Source pending-first display order is preserved. Foreign-endpoint receipts consume physical capacity without becoming current-endpoint uncertainty. A new take needs capacity for its start and future stop; ordinary setters and stages cannot consume its reserved stop slot. Existing continuously owned stop work remains available despite unrelated uncertain commands. V2 presence prevents handoff to an SDK owner that cannot interpret it. No receipt history is automatically deleted.

Concurrent explicit setters enter a FIFO bounded by32 commands and16MiB of encoded normalized arguments plus caller identity. Raw frontend arguments are released before waiting; active dispatch shares immutable request data. These bounds are not process-RSS guarantees. Queue time counts toward the original deadline, cancelled or expired queued calls create no intent and send nothing, and control/owned stop bypass the FIFO. Policy and complete receipt state are checked again at actual send. Operator effects serialize; arbitrary concurrent Source interleavings are not claimed identical.

Twelve static Source tools remain unported: five recording/named-output controls, five raw/batch/vendor/hotkey routes and two multi-step workflows. Stream Start/Stop/Toggle additionally remain excluded from sessions with owned recording/media adapters. All 75 Source read-only annotated tools are represented in the opt-in inventory. Richer MCP interfaces and default cutover retain separate qualification requirements.
