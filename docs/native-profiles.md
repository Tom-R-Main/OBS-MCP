# Native capability profiles

The persistent native service selects its profile once at startup with `OBS_MCP_NATIVE_PROFILE`. The default is `production`. The Rust entry enters this retained service by default over stdio or loopback HTTP. This document describes profile admission; artifact-specific qualification and shipping activation are recorded in [cutover status](full-rust-cutover.md).

```sh
OBS_MCP_STATE_DIR=/absolute/approved/private-state OBS_MCP_NATIVE_PROFILE=advanced native/target/release/obs-mcp-native
```

Production retains the existing guarded scene, preparation/recovery, Take and media workflows when their adapters are configured. It refuses direct recording Start/Toggle and arbitrary named Output Start/Stop/Toggle. A tool filter or dynamic group enable cannot promote those capabilities. Existing standalone Stream controls remain available only in the already-qualified configuration without Take/media adapters; their potentially delayed recording effects now also remain incompatible with later guarded reentry.

Advanced adds five fixed manual tools: `obs-start-record`, `obs-toggle-record`, `obs-start-output`, `obs-stop-output` and `obs-toggle-output`. Toggles send one atomic OBS request. Recording Start retains the same Source first-terminal-event/status confirmation helper; this is not recording identity or a future Stop/file-inspection grant. Named outputs may alias recording or delayed plugin outputs. Their names and successful acknowledgements do not certify a harmless target. Named Stop remains an ordinary explicit command, without the reserved owned recording Stop capability.

Advanced never constructs Take/Clip/media, Stage or preparation/recovery owners, even if a recording root is configured. It omits Stage/Take Scene, Apply/Capture Window, Prepare/Recover Demo, Snapshot/Restore, five Take/Clip tools and two media tools from discovery. Direct calls and the Service API refuse them too. Read-only OBS inspection and explicit manual StopRecord remain available. `obs-get-status` exposes the immutable profile and guarded-reentry metadata.

Before any advanced manual command can reach OBS, the same retained operation writer persists an identity-only receipt with its fixed request type. The payload/output name is not journaled. Prepared, Dispatching, Accepted, Rejected and Unknown history for these five commands or the existing Stream controls blocks later guarded-owner admission for that exact endpoint in the retained state namespace. Only the transport's typed NotDispatched outcome proves that attempt sent no effect. A new MCP process, socket, or inactive status sample does not clear the barrier.

Known Accepted history remains Accepted and does not become journal Unknown: independent explicit advanced commands and diagnostics may continue. Lost/malformed replies retain Unknown and refuse further mutation without replay. Human confirmation grants are inert, single-use, bound to the original caller/typed arguments/profile, and checked again against current policy before dispatch. Cancelling or losing the frontend does not release a dispatched operation before its retained observer settles.

This slice supplies no qualified OBS-incarnation/reset proof or automatic clear operation. Consequently switching back to guarded production after a possible advanced effect is deliberately refused. Deleting/copying the state namespace, changing endpoint aliases or editing receipt files is not qualified clean-state evidence. Protection assumes the approved namespace and exact endpoint binding remain intact; it is not a filesystem sandbox against a same-user process or proof against a separately configured competing controller.

The catalog union is 178 implemented tool names across native profiles. Production with all host adapters exposes 164; Advanced exposes 163 ordinary tools, with three dynamic controllers counted separately when enabled. These are profile projections, not 178 tools simultaneously available in one runtime.

Advanced also owns `obs-call-request`, `obs-batch`, `obs-call-vendor-request` and the two hotkey routes. Raw requests admit only the pinned 147 request names; wrapped reads retain the original write/open-world tool policy. Opaque request data is preserved after Source schema stripping and JavaScript numeric normalization. Vendor replies retain the full envelope. No wrapped method string borrows an owned recording Stop, critical lane, Take/file inspection or recovery capability.

A batch is one checked op8 containing 1–100 requests, using only serial-realtime or serial-frame, preserving haltOnFailure, canonical per-item identities and complete/halting-prefix result counts. It is never split, retried or replayed. Its one original budget uses the actual Source formula: 10,000 ms plus each numeric Sleep.sleepMillis and each numeric Sleep.sleepFrames / 30 * 1,000, in either execution mode. This formula does not sample the configured video frame rate. Native qualification caps the resulting total at 600 seconds; nonpositive, nonrepresentable or over-cap defaults refuse before connection/send. Accepted batches subtract elapsed queue time once rather than resetting a budget per item. OBS may continue a batch Sleep after frontend cancellation, EOF or transport timeout; this profile does not promise that an explicit Stop interrupts the OBS batch executor. Lost or invalid response vectors remain Unknown, with no sub-batch replay.

Single raw capture-property enumeration runs the same Source GetInputSettings guard using string selectors and the retained session. Guarded ScreenCaptureKit application/display lists and unconfigured XComposite window enumeration remain refused. A batch containing guarded enumeration is refused before dispatch even if earlier items would change the source. Native batch response matching is deliberately stricter than Source's permissive sorting: malformed, incomplete non-halting, duplicate, foreign or noncanonical result identities become Unknown rather than a guessed success.

`obs-press-input-property-button` is now Advanced-only. This is an intentional availability change from the previously qualified production inventory: libobs invokes a plugin callback whose ACK does not prove descendant work ended. Its existing fixed metadata receipt now carries the same persistent guarded-reentry incompatibility, including retained prior receipts. No payload, vendor, hotkey, output name or file path is stored in these compatibility receipts. Other cooperative plugin assumptions are not upgraded into a blanket descendant-settlement guarantee.

Qualification uses actual SDK2.4 Source/fake-OBS comparisons and retained Service tests. The opaque slice additionally preserves known Accepted/Rejected facts independently of incompatibility, and only typed NotDispatched releases a prepared barrier. These controls do not prove live named output aliases, rendered content, another desktop platform, TLS or a license change. Current HTTP and release evidence is recorded in [cutover status](full-rust-cutover.md).
